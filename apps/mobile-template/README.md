# Mobile Template

iOS and Android [Expo Router](https://docs.expo.dev/router/introduction) app with native tabs,
system light and dark themes, and a layout that adapts to tablets and foldables.

`ios/` and `android/` are generated by `expo prebuild` and ignored; change native code through
config plugins in `app.json`. Builds run locally, with no EAS.

The Device tab demos
[@pandoks.com/react-native-notifications](/packages/react-native-notifications). Set
`EXPO_PUBLIC_BACKEND_URL` when building to register its push token with the app's backend.

Android gets a push token only from builds run in `sst shell`: it links the stage's Firebase app
from [infra/firebase.ts](/infra/firebase.ts), and `app.config.ts` writes its `google-services.json`.
Any non-production stage gets the shared `pandoks-dev` project. Production's config is never read
locally, and no release build job exists yet. Rebuild `android/` so prebuild copies the file:

```sh
rm -rf android
pnpm --dir ../.. sst shell --stage <stage> -- \
  pnpm --filter @pandoks.com/mobile-template android --variant release
```

Run from this directory:

```sh
mise install    # Ruby, CocoaPods, Java, and Maestro from this app's mise.toml
pnpm ios        # build and run on an iOS simulator
pnpm android    # build and run on an Android emulator
pnpm test:unit
pnpm test:e2e   # Maestro flows in e2e/, against the running app
```
