# Mobile Template

iOS and Android [Expo Router](https://docs.expo.dev/router/introduction) app with native tabs,
system light and dark themes, and a layout that adapts to tablets and foldables.

`ios/` and `android/` are generated by `expo prebuild` and ignored; change native code through
config plugins in `app.json`. Builds run locally, with no EAS.

`targets/watch` is a SwiftUI watchOS app that
[`@bacons/apple-targets`](https://github.com/EvanBacon/expo-apple-targets) adds at prebuild and
embeds in the iOS app. It talks to the phone through
[`packages/react-native-watch`](../../packages/react-native-watch). On simulators, pair a watch with
`xcrun simctl pair` and install the built app's `Watch/watch.app` on it with `xcrun simctl install`.
Device builds need your team ID in `ios.appleTeamId`, which the plugin applies to every target.

`targets/wear` is its Wear OS counterpart in Compose for Wear OS, added at prebuild as the `:wear`
Gradle module with the phone app's ID, signing key, R8 setting, and version name. Its version code
is the phone's plus 1,000,000,000, since Play needs codes unique across form factors. Install it on
a Wear OS emulator with `ANDROID_SERIAL=<watch serial> ./gradlew :wear:installDebug` from
`android/`. The phone needs the Pixel Watch app from the Play Store, so use a Google Play emulator
image, then pair with Device Manager's **Pair Wearable** in Android Studio.

Run from this directory:

```sh
mise install    # Ruby, CocoaPods, Java, and Maestro from this app's mise.toml
pnpm ios        # build and run on an iOS simulator
pnpm android    # build and run on an Android emulator
pnpm test:unit
pnpm test:e2e   # Maestro flows in e2e/, against the running app
```
