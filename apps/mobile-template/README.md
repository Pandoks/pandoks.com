# Mobile Template

iOS and Android [Expo Router](https://docs.expo.dev/router/introduction) app with native tabs,
system light and dark themes, and a layout that adapts to tablets and foldables.

`ios/` and `android/` are generated by `expo prebuild` and ignored; change native code through
config plugins in `app.json`. Builds run locally, with no EAS.

Run from this directory:

```sh
mise install    # Ruby, CocoaPods, Java, and Maestro from this app's mise.toml
pnpm ios        # build and run on an iOS simulator
pnpm android    # build and run on an Android emulator
pnpm test:unit
pnpm test:e2e   # Maestro flows in e2e/, against the running app
```

## Updates

Release builds check `updates.pandoks.com` with `expo-updates` in the background on launch and apply
a new update on the next launch. The runtime version is the native
[fingerprint](https://docs.expo.dev/versions/latest/sdk/fingerprint/), so an update only reaches
builds with the same native code, and `certificate.crt` verifies the `UpdatesSigningKey` signature.

The cluster serves the update baked into the `mobile-template-updates` image
([packages/updates](../../packages/updates/README.md)), which `build-and-publish.yaml` rebuilds when
the app changes. In production that's the digest pinned in `kube/updates.yaml`: merging Renovate's
bump releases the update. To roll back, revert the change on `main` and merge the next bump, since
phones keep the newest update they have. Local and dev clusters serve the checkout's own image.

To try a dev update, build against `updates-dev.pandoks.com`, then change some JS and deploy the dev
cluster from that branch once `build-and-publish.yaml` has built its image:

```sh
export UPDATES_ENVIRONMENT=dev
rm -rf ios && pnpm ios --configuration Release
rm -rf android && pnpm android --variant release
```
